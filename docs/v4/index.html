SUA IA, no terminal.

O Tell-ai leva modelos de linguagem para onde o seu código já vive: o shell. Pergunte, pipeie, deixe o modelo propor comandos — você aprova cada um. A mesma engine vira SDK no seu código — e, com tell -w, um sandbox no navegador.

tell-ai — sessão de exemplo

§ 01 — por quê

Copiar, colar, formatar, repetir.

fluxo — antes / depoisunified
--- a/fluxo/sem-tell-ai
+++ b/fluxo/com-tell-ai
1- abrir uma aba nova no navegador
2- digitar o endereço do chat
3- autenticar (de novo)
4- colar código + contexto à mão
5- copiar a resposta e reformatar
6- voltar ao editor e colar de novo
1+ git diff --staged | tell -i "review this change"

~23 minutos

é o que estudos de atenção estimam para retomar o foco depois de uma interrupção. Cada ida até o navegador é uma delas. O Tell-ai encurta o caminho para um comando.

você no comando

O modelo propõe comandos entre tags <RUN> — e nada roda sem a sua confirmação. Com -y os seguros rodam sozinhos, mas padrões de alto risco (sudo, rm -rf, curl|sh…) sempre perguntam.

shell, código e a aba.

CLI no terminal, SDK no seu código — e o sandbox web (v0 preliminar) via tell -w: terminal, explorador de arquivos e chat no navegador, ancorados num diretório.

§ 02 — primeiros passos

Três comandos até a primeira resposta.

01

Instale

Um binário, uma pergunta. Nada de daemon rodando em segundo plano.

$ npm install -g tell-ai
02

Aponte uma chave

Qualquer vendor que você já usa — via ambiente ou um arquivo ~/.config/<vendor>.token. Sem cadastro novo.

$ export DEEPSEEK_API_KEY="…"
03

Converse

A letra já escolhe o modelo — d de DeepSeek Flash (que já nasce em high), D de Pro, g de GPT.

$ tell d "run ls -la" # confirma antes de executar

§ 03 — recursos

Construído como ferramenta unix.

TELL(1) · General Commands Manual

01<RUN>

O modelo propõe comandos entre tags e você aprova um a um. Timeout de 120s por comando; sudo, rm -rf, mkfs, curl|sh e escritas em /etc são bloqueados sempre.

02|  -i

Pipes de verdade: npm test 2>&1 | tell -i "why are these failing?" — stdin vira contexto, não vira bagunça.

03-m d

142 aliases para os modelos de OpenAI, Anthropic, Google, xAI, DeepSeek, Alibaba, Z.ai, Moonshot, Meta e Xiaomi + self-hosted — cada um com sua régua de thinking. O default é g (via TELL_MODEL). resolvedor interativo ↘

04--stream
--think

--stream imprime token a token; --think mostra o reasoning. Só mudam o que aparece: log, contexto e extração de <RUN> ficam idênticos.

05--chain

Multi-step: o modelo roda um comando, lê a saída e continua — até 8 rodadas até a resposta final.

06-c / --ctx

Contexto persistente por diretório+modelo em ~/.ai/tell_context. Nomeie com --ctx %projeto, retome por @0, reset com -n; --ctx sem ref é prompt do contexto default.

07-l

tell -l lista contextos (@N) e conversas (%N), busca por termo, reimprime com -l @0 — sem modelo, sem chave, sem rede. Log completo em ~/.ai/tell_history.

08--require-
approval

Postura de execução explícita: com -y, seguros rodam direto e os de risco perguntam; sem -y, tudo pergunta. Comandos que tocam fora do cwd — leitura inclusive — sempre perguntam.

09q / v

Modelos self-hosted com a mesma ergonomia: q para endpoints locais, v para Vast — e qualquer vendor sem handler cai no provider OpenAI-compatible genérico.

10tell -w

O sandbox web v0 no navegador: terminal, explorador de arquivos e chat ancorados ao diretório. --stream, --think, --chain, -y, --no-exec e --require-approval são repassados. ver a seção ↘

§ 06 — sdk

A mesma tell(), fora do shell.

$ npm add @tell-ai/sdk

ou bun add @tell-ai/sdk — pacote próprio da biblioteca, separado da CLI.

sdk/exemplo.ts — Node / Bun 
// o "tell --no-exec" como função: chama o modelo e devolve
// o texto com tags <RUN> e reasoning já removidas
import { tell, create_ask_ai, get_model, MODELS } from '@tell-ai/sdk';

const resposta = await tell('resuma o diff não commitado', {
  keys: { deepseek: process.env.DEEPSEEK_API_KEY },
});

// streaming token a token — eventos NDJSON (reasoning | text)
const ai = create_ask_ai('g', { keys: { openai: process.env.OPENAI_API_KEY } });
for await (const ev of ai.ask_stream('explique este repo')) {
  if (ev.type === 'text') process.stdout.write(ev.text);
}

// também exportados: MODELS (142 aliases), get_model() (o
// ModelHandle cru para o seu próprio generateText),
// get_system_prompt, extract_runs · strip_run_tags ·
// sanitize_reasoning · summarize_context
browser/index.html — zero build, via CDN 
<script src="https://unpkg.com/@tell-ai/sdk"></script>
<script>
  // IIFE global — roda até em file://
  TellSDK.tell('olá', { keys: { google: MINHA_CHAVE } });
</script>

12 vendors via keys/urls: openai · anthropic · google · xai · deepseek · cerebras · moonshotai · openrouter · alibaba (qwen) · zai (glm) · meta (llama) · xiaomi (mimo) + vast/local self-hosted. Budget de reasoning resolvido por vendor (max vira o teto de cada um); provider caches por base URL e credencial.

dois pacotes, duas licenças

A CLI (tell-ai) é GPL-3.0. O SDK (@tell-ai/sdk) é MIT — pode embutir em produto fechado sem dor de cabeça.

zero process.env

O SDK nunca lê o ambiente: chaves e base URLs são injetadas via keys e urls. É o que o torna browser-safe — e urls aceita proxy CORS, como no examples/web/ do repo.

a fundação do sandbox

Os builds de browser já sobem numa <script> tag pura — é por cima deles que o sandbox v0 do §07 foi construído.

o que vem depois

preliminar significa: falta o que você reclamar — abra uma issue e a v1 sai disso.

fora do localhost: modo seguro export TELL_TOKEN=$(openssl rand -hex 32)
tell-web --cwd ~/projeto

· Bearer em todo /api/* · WS via ?token=
· token só em memória — reload pede de novo
· verify limitado a 5 tentativas/15 min/IP
· filhos nascem sem TELL_TOKEN nem chaves
· checagem de Host/Origin contra DNS rebinding

Segurança desde o v0: Auto-Run é opt-in (navegador novo sempre pergunta antes), --no-exec trava no servidor (/api/execute → 403) e vence preferências salvas. A base é o build IIFE do SDK — a doc completa está em packages/web/README.md.
