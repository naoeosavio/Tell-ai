SUA IA, no terminal.

O Tell-ai leva modelos de linguagem para onde o seu código já vive: o shell. Pergunte, pipeie, deixe o modelo propor comandos — você aprova cada um. A mesma engine vira SDK no seu código — e, com tell -w, o web no navegador.

§ 01 — por quê

Copiar, colar, formatar, repetir.

fluxo — antes / depoisunified
--- a/fluxo/sem-tell-ai
+++ b/fluxo/com-tell-ai
1- abrir uma aba nova no navegador
2- digitar o endereço do chat
3- autenticar (de novo)
4- colar código + contexto à mão
5- copiar a resposta e reformatar
6- voltar ao editor e colar de novo
1+ git diff --staged | tell -i "review this change"

~23 minutos

é o que estudos de atenção estimam para retomar o foco depois de uma interrupção. Cada ida até o navegador é uma delas. O Tell-ai encurta o caminho para um comando.

você no comando

O modelo propõe comandos entre tags <RUN> — e nada roda sem a sua confirmação. Com -y os seguros rodam sozinhos, mas padrões de alto risco (sudo, rm -rf, curl|sh…) sempre perguntam.

shell, código e a aba.

CLI no terminal, SDK no seu código — e o web (v0.3.2) via tell -w: terminal, explorador de arquivos e chat no navegador, ancorados num diretório.

§ 02 — primeiros passos

Três comandos até a primeira resposta.

01

Instale

Um binário, uma pergunta. Nada de daemon rodando em segundo plano.

$ npm install -g tell-ai
02

Aponte uma chave

Qualquer vendor que você já usa — via ambiente ou um arquivo ~/.config/<vendor>.token. Sem cadastro novo.

$ export DEEPSEEK_API_KEY="…"
03

Converse

A letra já escolhe o modelo — d de DeepSeek Flash (que já nasce em high), D de Pro, g de GPT.

$ tell d "run ls -la" # confirma antes de executar

§ 03 — recursos

Construído como ferramenta unix.

TELL(1) · General Commands Manual

01<RUN>

O modelo propõe comandos entre tags e você aprova um a um. Timeout de 120s por comando; sudo, rm -rf, mkfs, curl|sh e escritas em /etc são bloqueados sempre.

02|  -i

Pipes de verdade: npm test 2>&1 | tell -i "why are these failing?" — stdin vira contexto, não vira bagunça.

03-m d

152 aliases para os modelos de OpenAI, Anthropic, Google, xAI, DeepSeek, Alibaba, Z.ai, Moonshot, Meta e Xiaomi + self-hosted — cada um com sua régua de thinking. O default é g (via TELL_MODEL); qualquer endpoint próprio entra como custom:<model> — e tell --models lista o catálogo do endpoint, agrupado por wire. resolvedor interativo ↘

04--stream
--think

--stream imprime token a token; --think mostra o reasoning. Só mudam o que aparece: log, contexto e extração de <RUN> ficam idênticos.

05--chain

Multi-step: o modelo roda um comando, lê a saída e continua — até 8 rodadas até a resposta final.

06-c / --ctx

Contexto persistente por diretório+modelo em ~/.ai/tell_context. Nomeie com --ctx %projeto, retome por @0, reset com -n; --ctx sem ref é prompt do contexto default.

07-l

tell -l lista contextos (@N) e conversas (%N), busca por termo, reimprime com -l @0 — sem modelo, sem chave, sem rede. Log completo em ~/.ai/tell_history.

08--require-
approval

Postura de execução explícita: com -y, seguros rodam direto e os de risco perguntam; sem -y, tudo pergunta. Comandos que tocam fora do cwd — leitura inclusive — sempre perguntam.

09q / v

Modelos self-hosted com a mesma ergonomia: q para endpoints locais, v para Vast — e qualquer vendor sem handler cai no provider OpenAI-compatible genérico.

10tell -w

O web v0.3.2 no navegador: terminal, explorador de arquivos e chat ancorados ao diretório. --stream, --think, --chain, -y, --no-exec e --require-approval são repassados. ver a seção ↘

11@tell-ai/
core

O runtime compartilhado (MIT): contrato injetável, executor Node, risco base, caminhos fail-closed e os limites operacionais. A CLI e o web são adaptadores finos sobre ele. ver a seção ↘

12.tellrc

Config em INI, sem JSON: ~/.tellrc (usuário) e <cwd>/.tellrc (projeto). Precedência flag › env › projeto › usuário; o deny só acumula. Perfis, aliases, temperatura, system-file e limites. --profile node (ou security, devops, ou o seu) troca a postura.

13--exec-timeout
--max-chain

Todo número tem um dono: --exec-timeout (120s), --stdin-timeout, --stdin-max-bytes, --context-max-chars, --max-chain (1..128), --max-buffer e --output-max-bytes. Precedência flag › env › tellrc › default — e valor inválido falha antes de qualquer chamada ao modelo.

14--system
--temperature

Contexto que você controla: --system (instruções custom), --system-file (64 KB) e --temperature (0..2) — por flag, env ou .tellrc. As instruções custom entram antes do prompt de segurança, nunca no lugar dele.

§ 06 — sdk

A mesma tell(), fora do shell.

$ npm add @tell-ai/sdk

ou bun add @tell-ai/sdk — pacote próprio da biblioteca, separado da CLI.

sdk/exemplo.ts — Node / Bun 


import { tell, create_ask_ai, get_model, MODELS } from '@tell-ai/sdk';

const resposta = await tell('resuma o diff não commitado', {
  keys: { deepseek: process.env.DEEPSEEK_API_KEY },
});


const ai = create_ask_ai('g', { keys: { openai: process.env.OPENAI_API_KEY } });
for await (const ev of ai.ask_stream('explique este repo')) {
  if (ev.type === 'text') process.stdout.write(ev.text);
}

quatro entradas, mesmo código
@tell-ai/sdkESM + CJS + tiposNode / Bun
@tell-ai/sdk/browserESM bundleadobundlers
@tell-ai/sdk/browser-globalIIFE → TellSDK<script>, CDN, file://
@tell-ai/sdk/puresó o protocolo, sem providero core consome

dois pacotes, duas licenças

A CLI (tell-ai) é GPL-3.0. O SDK (@tell-ai/sdk) é MIT — pode embutir em produto fechado sem dor de cabeça.

zero process.env

O SDK nunca lê o ambiente: chaves e base URLs são injetadas via keys e urls. É o que o torna browser-safe — e urls aceita proxy CORS, como no examples/web/ do repo.

a fundação do web

Os builds de browser já sobem numa <script> tag pura — é por cima deles que o web v0.3.2 do §08 foi construído.

§ 07 — core

O runtime que a CLI e o web compartilham.

$ npm add @tell-ai/core

ou bun add @tell-ai/core — o runtime compartilhado (MIT), entre o SDK e os hosts.

core/exemplo.ts — Node / Bun 

import {
  createTellRuntime, create_node_executor, create_base_risk_port,
} from '@tell-ai/core';


const runtime = createTellRuntime({
  model,                                    
  exec: true,
  executor: create_node_executor(),   
  risk: create_base_risk_port('permissive'),
  approval: async ({ script }) => 'approved',
});


const r = await runtime.run('roda os testes e resume');
o que o core possui — um dono por coisa
createTellRuntimecontrato injetável de um turno
create_node_executorbash + timeout + kill do grupo
assess_base_riskrisco base (permissive / strict)
canonical_pathcaminhos fail-closed
parse_runtime_limitslimites: flag › env › tellrc › default
build_project_contextárvore + README/AGENTS do projeto

um dono, dois hosts

A CLI e o web são adaptadores finos sobre o core: eles parseiam flags, renderizam e injetam as portas. Loop, execução, risco e limites vivem num lugar só — o mesmo código decide nos dois.

efeitos são explícitos

Sem exec: true e executor e aprovação, o runtime apenas reporta o comando — e nunca o roda. A mesma redaction boundary mascara stdout, callbacks, log e contexto.

MIT, e browser-safe

O pacote é MIT (packages/core/LICENSE é MIT próprio) e a condition browser entrega o runtime inteiro: createTellRuntime, create_core_runtime e run_primitive_loop. O core só depende do SDK pela entry @tell-ai/sdk/pure (sem provider, sem rede, sem builtin), então o bundle é autocontido — zero import, ~30 KB. Ficam de fora só o que é Node: exec, paths, project-context e sdk-config.
